# Asteroids Deluxe C conversion — conventions

A faithful C translation of the 6502 game logic, building a real DVG
display list rather than calling a drawing API.

**Base revision: rev 2** (MAME `astdelux2`) — the build Atari's source
archive documents, so every routine translated here has its author's own
name and comment. Rev 3 differs by 231 instructions across 40 regions;
those are layered on later, not ported separately. See
[`../disasm/README.md#revisions`](../disasm/README.md#revisions).

Read before translating a module:

- [`../disasm/astdelux2_main.asm`](../disasm/astdelux2_main.asm) — the listing, every routine named and commented
- [`../disasm/FUNCTIONS.md`](../disasm/FUNCTIONS.md) — per-routine index
- [`../disasm/MAINLINE_NOTES.md`](../disasm/MAINLINE_NOTES.md), [`GAMEPLAY_NOTES.md`](../disasm/GAMEPLAY_NOTES.md), [`VECTOR_NOTES.md`](../disasm/VECTOR_NOTES.md), [`SOUND_NOTES.md`](../disasm/SOUND_NOTES.md), [`BOOT_AND_NMI_NOTES.md`](../disasm/BOOT_AND_NMI_NOTES.md)

## Rules

**1. One C function per named routine**, same name lowercased with an
`ad_` prefix: `NEWAST` → `ad_newast()`. Keep a comment giving the ROM
address and a one-line role — that is the link back to the listing.

**2. All state lives in `g`** (`astdelux_state.h`, generated by
`disasm/mkstate.py` from `PG0123.MAC`). Use the field named after the
RAM symbol. If a cell has no field, it is because the source does not
declare it — check `astdelux_defines.asm` before adding one, and never
invent parallel state.

The header carries a `_Static_assert` per field pinning its offset to
the 6502 address. Do not weaken those: they are what makes it safe to
translate the ROM's pointer arithmetic literally.

**3. Keep the parallel-array object model.** Slots 0-24 are rocks, 25
the ship, 26 the saucer, 27-28 its torpedoes, 29-32 the ship's. The ROM
indexes *across* those boundaries deliberately — `COLIDE` walks
`SHPPIX,x` for x = 0..7, running off one "array" into the next — so use
`ad_obj()`, `ad_xinc()` and friends, which return the base of a run.
Turning these into structs would break the idiom silently.

**4. Two players, one address.** `BNKSEL` swaps pages 2 and 3; the code
never indexes by player. Reach the active page through `AD_P` and swap
with `ad_sbank()`. Do not add a player index.

**5. Build a real display list.** Vector RAM (`g.vram`) is modelled, and
the `VG*` builders append to it exactly as the ROM does. Two reasons,
both load-bearing:

- the shapes are copied *and modified* on the way in — `CPYVEC` applies
  sign and swap masks to rotate the ship, and ORs in the intensity that
  the ship frames are stored without — so the list is where the drawing
  actually happens;
- it gives the strongest differential test available: generated vector
  RAM can be diffed byte-for-byte against a hardware dump.

That second point means **byte-exact quirks are load-bearing**. `VGHALT`
writes `B0 B0`, not `00 B0`, because the ROM stores the same byte twice;
the DVG ignores the low byte but a comparison would not.

**6. Fixed point stays fixed point.** Velocities are `S9999.BBB`;
positions are split across separate high and low arrays a page apart.
Keep that layout — it is why `MOTION` reads two arrays rather than one
16-bit value.

**7. Timing is NMI ticks.** The NMI runs at ~4 ms and bumps `SYNC` every
fourth interrupt; the main line spins on `SYNC` and consumes it with a
shift. Do not convert to seconds or floats. Frame pacing is the host's
job. Note that missing two ticks is *fatal by design* — the NMI hangs so
the watchdog resets the board — so a host must not let the loop stall
silently.

**8. Hardware only through `ad_hw_*`.** Never poke addresses. Switch
reads take the full 6502 address (`$2004`) so call sites read like the
listing.

**9. Preserve quirks that affect play; drop pure hardware artefacts, and
say so.** Keep the shield drain rate, the wave-end condition, the
attract mode running `MOTION`/`COLIDE` with no ship. Watchdog kicks and
the anti-tamper checksum can be dropped — but leave a comment where they
were, as `mainline.c` does for the checksum slice.

**10. Plain C11.** No dynamic allocation. No globals besides `g` and
const tables.

**11. ROM tables are read from the ROM, at their address.** Both ROM
regions are exported as data by `disasm/mkrom.py` (`astdelux_rom.c`),
and `ad_rom(addr)` returns the byte the 6502 would read. So
`lda SINCOS,x` becomes `ad_rom(AD_SINCOS + x)`, with `AD_SINCOS` defined
as the table's address in `astdelux.h`. Nothing is transcribed by hand:
a wrong index is a wrong address, findable in the listing, not a wrong
copy. Add a `#define AD_<NAME> 0x....` for each table a module reads;
do not copy the bytes into a C array.

**12. Registers become parameters and return values, flags become
`bool`.** A routine's entry registers are its parameters in A, X, Y
order (an object slot index stays `uint8_t`); a result the ROM leaves in
a register is the return value; a result the caller tests as a flag is
a `bool`, named for what *set* means (`true` = carry set = "starting a
new game"). Zero-page temporaries the routine shares with its callers
(`TEMP1`, `R0`..`R9`, `XT`) stay in `g.zp`, because the ROM passes
values through them between routines. State a routine only uses
internally may become a local. The signatures of everything called
across modules are fixed in `astdelux.h`; a module's private helpers are
`static`.

**13. Rev 2 is what runs; rev 3 is a switch.** The port is rev 2, exact,
bugs included (the saucer's `cmp $06` in `EFIRE` is a typo in Atari's
source and every rev 2 ROM has it; it stays). Where rev 3 behaves
differently, the rev 3 code sits beside the rev 2 code behind
`if (ad_hw_rom_rev() >= 3)`, at the point where the listings diverge,
with the rev 3 addresses in the comment. The hosts set the revision
from `[game] revision` in the ini (Windows) or `--rev3` (headless);
2 is the default. Rev 3 data that the rev 2 image does not contain is
the one allowed exception to rule 11: a `static const` table beside the
code that reads it, with its rev 3 address, until the rev 3 image is
exported alongside the rev 2 one. Never let rev 3 leak into the rev 2
path, and never gate on anything but `ad_hw_rom_rev()`.

## Module map

| file | contents |
|---|---|
| `mainline.c` | `START`, the frame loop, `PWRON`, `SBANK` |
| `vgutil.c` | `DSTCUT.MAC` — the display-list builders, plus `VGBLNK` and `DIGITS` |
| `message.c` | `DSTMSG.MAC` — `VGMSG` and the packed text, the copyright check |
| `mathrom.c` | `SIN`/`COS`, `ATAN`, `DIVIDE`, `MULT`, `RANGE`, `CPUTD`, `SCALER` |
| `frame.c` | `INIT`, `SINIT`, `PKYTST`, the checksum slice |
| `objects.c` | `MOTION`, `COLIDE`, `DSTRCT`, `CPYPOS`, `SPLIT`, `NEWAST`, `NEWVEL`, `NEWSHP`, `SEARCH`, `BOUNCE` |
| `draw.c` | `PICTUR`, `SHPPIC`, `SHPEXP`, `CPYVEC`/`CPYVYX`, `CPXROT`, `ROTAST`, `TRIPIX` |
| `player.c` | `SHIELD`, `FIRE`, `MOVE` |
| `enemy.c` | `ENEMY`, `EFIRE`, `ATTACK`, `SETTIP`, the special rock |
| `score.c` | `PARAMS`, `SCORES`, `UPDATE`, `GETINT`, `POINTS`, `LIVES`, `CHKST` |
| `sound.c` | `SOUNDS`, `CSOUND`, `SNDON`/`SNDOFF`, `INISOU`, `DIASND` |
| `nmi.c` | `NMI` and the `DCIN65.MAC` coin machinery |
| `earom.c` | `EAUPD`, `STEAROM` |
| `stest.c` | the cabinet self-test — `STEST3`'s ROM checksum and bank-select test, `STEST5`/`STEST6`/`STEST7`, `SWCH`, `BONDSP` |
| `pokey.c` | the POKEY (Atari C012294) sound and RNG core, translated from the AAE emulator's core (`aae_pokey.cpp`), with the poly generators and reset model from MAME's `pokey.cpp`; not a ROM routine — the chip is hardware the ROM talks to — so it carries no `ad_` prefix and no platform includes |
| `er2055.c` | the ER2055 EAROM (GI, 64x8) behind `EACTL`/`EADAL`/`EAIN`, translated from MAME 0.286's `er2055.cpp` as `asteroid.cpp` wires it; same footing as `pokey.c` — hardware the ROM talks to, no `ad_` prefix, no platform includes |
| `astdelux_rom.c` | **generated** — the ROM images, read through `ad_rom()` |
| `tests/stubs.c` | empty — every routine is translated; kept as the staging hook for `tests/build_mod.bat` |

Not translated, by decision: `PWRON`'s RAM test (a C port has nothing to
test), `STEST1`'s bad-RAM beep on the 3 kHz clock, `STOP`'s spin until
the self-test switch is pushed, the 3 kHz timing loops and `SWCH_5`'s
delay loop, and the watchdog strobes in the self-test display loop —
the host paces frames and reads switches itself (rules 7/9). `VGVCTR`
and `VGJMPL`, which nothing calls, are also not translated.
